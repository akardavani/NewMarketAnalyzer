راهنمای انتشار MarketAnalyzer

نسخه‌ی تنظیمات محیطی و Publish امن؛ تنظیمات محرمانه داخل appsettings.json پایه نگهداری نمی‌شوند.

۱) آماده‌سازی تنظیمات

  1. برای API فایل backend/MarketAnalyzer.Api/appsettings.Local.example.json را به appsettings.Local.json کپی کنید.
  2. برای UI فایل frontend/admin/MarketAnalyzer.Ui.Server/appsettings.Local.example.json را به appsettings.Local.json کپی کنید.
  3. مقادیر اتصال SQL، SigningKey، کلید Stimulsoft، RabbitMQ و ApiKey را با مقادیر معتبر جایگزین کنید.
  4. برای سرور از فایل‌های appsettings.Production.example.json استفاده کنید، نام آن‌ها را به appsettings.Production.json تغییر دهید و فقط روی سرور نگه دارید.
فایل‌های محیطی واقعی عمداً در Git قرار نمی‌گیرند. فایل پایه نباید شامل password، token یا connection string واقعی باشد.

۲) Publish محلی

از ریشه‌ی ریپو، PowerShell را اجرا کنید:

powershell -NoProfile -ExecutionPolicy Bypass -File .\project-workspace\scripts\Publish-MarketAnalyzer.ps1 -EnvironmentName Local

اگر Angular از قبل build شده و فقط می‌خواهید بسته‌ی .NET ساخته شود:

powershell -NoProfile -ExecutionPolicy Bypass -File .\project-workspace\scripts\Publish-MarketAnalyzer.ps1 -EnvironmentName Local -SkipSpaBuild

خروجی جدید در مسیرهای زیر ساخته می‌شود:

artifacts/publish/Local/<timestamp>/Api artifacts/publish/Local/<timestamp>/Ui

در هر دو پوشه فایل appsettings.Local.json نیز کپی می‌شود و فایل READY.txt پایان موفق فرایند را مشخص می‌کند.

۳) اجرای بسته‌ی محلی

# API
$env:ASPNETCORE_ENVIRONMENT = "Local"
dotnet .\artifacts\publish\Local\<timestamp>\Api\MarketAnalyzer.Api.dll --urls "https://localhost:7260"

# UI (در ترمینال جدا)
$env:ASPNETCORE_ENVIRONMENT = "Local"
dotnet .\artifacts\publish\Local\<timestamp>\Ui\MarketAnalyzer.Ui.Server.dll --urls "https://localhost:7213"

سپس پنل را در https://localhost:7213 و Swagger را در https://localhost:7260/swagger باز کنید.

۴) Publish برای سرور

  1. روی سیستم توسعه، appsettings.Production.json را برای API و UI آماده کنید.
  2. مقدار CorsOptions:AllowedOrigins را برابر origin واقعی پنل قرار دهید.
  3. بسته را بسازید:
powershell -NoProfile -ExecutionPolicy Bypass -File .\project-workspace\scripts\Publish-MarketAnalyzer.ps1 -EnvironmentName Production

خروجی در artifacts/publish/Production/<timestamp> قرار می‌گیرد. پوشه‌های API و UI را جداگانه به سرور منتقل کنید.

تنظیم IIS

  • برای API و UI دو Application Pool مستقل با No Managed Code بسازید.
  • برای هر پوشه یک IIS Site یا Application بسازید و binding دامنه/HTTPS را تنظیم کنید.
  • فایل‌های web.config تولیدشده را نگه دارید و Hosting Bundle متناسب با .NET 8 و .NET 9 را روی سرور نصب کنید.
  • پس از کپی، سایت‌ها را recycle کنید و ابتدا Swagger، سپس ورود پنل و یک درخواست API را بررسی کنید.
برای جلوگیری از مخلوط شدن نسخه‌ها، خروجی هر بار در پوشه‌ی timestamp‌دار ساخته می‌شود. پوشه‌ی قبلی را با فایل‌های نسخه‌ی جدید ادغام نکنید.

۵) Publish از Visual Studio

برای API و UI در بخش Publish، پروفایل Local یا Production را انتخاب کنید. پروفایل‌ها از نوع Folder، حالت Release، runtime ویندوز x64 و self-contained هستند.

پروفایل‌ها:

backend/MarketAnalyzer.Api/Properties/PublishProfiles/Local.pubxml backend/MarketAnalyzer.Api/Properties/PublishProfiles/Production.pubxml frontend/admin/MarketAnalyzer.Ui.Server/Properties/PublishProfiles/Local.pubxml frontend/admin/MarketAnalyzer.Ui.Server/Properties/PublishProfiles/Production.pubxml

خطاهای متداول

  • Missing appsettings...: فایل محیطی با نام دقیق appsettings.<Environment>.json را کنار csproj بسازید.
  • خطای SQL: مقدار ConnectionStrings:Defualt و دسترسی کاربر SQL را بررسی کنید؛ نام کلید فعلی عمداً Defualt باقی مانده است.
  • 401 یا خطای ورود: JsonTokenOptions:SigningKey در API و IdentityClientOptions:ApiKey در UI باید معتبر باشند.
  • CORS: origin دقیق پنل را بدون slash انتهایی در AllowedOrigins قرار دهید.
  • صفحه‌ی خالی پنل: build Angular، وجود فایل‌های wwwroot و مقدار AppOptions:ApiUrl را بررسی کنید.
