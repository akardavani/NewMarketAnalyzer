# Repository guidance

Before making a non-trivial change, read [the project knowledge index](docs/PROJECT_KNOWLEDGE.md) and the relevant domain guide it links to. Inspect the current implementation before relying on documented behavior.

When a change adds or corrects a lasting project fact, architecture decision, constraint, verification result, or next step, update the document of record for that domain in the same change. Keep this repository-wide index focused on navigation and cross-domain guidance; keep implementation details in their domain documents. Date measured or environment-specific findings, distinguish verified behavior from proposals, and mark superseded guidance clearly.
