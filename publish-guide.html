راهنمای گرفتن خروجی Publish محلی MarketAnalyzer

این راهنما برای ساخت بسته روی ویندوز و نگهداری خروجی روی همین رایانه است. پروفایل‌ها برای نصب روی سرور یا انتشار عمومی تنظیم نشده‌اند.

با تغییر مسیر پروژه‌ها، target frameworkها، تنظیمات اجرای محلی یا روش ساخت Angular، این راهنما را هم‌زمان به‌روزرسانی کنید.

۱. پروفایل‌های انتشار

  • API: backend/MarketAnalyzer.Api/Properties/PublishProfiles/Local.pubxml — تنظیم‌شده برای Release، net8.0، win-x64 و self-contained.
  • UI Server: frontend/admin/MarketAnalyzer.Ui.Server/Properties/PublishProfiles/Local.pubxml — تنظیم‌شده برای Release، net9.0، win-x64 و self-contained.
  • فرایند Publish پروژهٔ UI Server، پروژهٔ Angular را با npm ci و npm run build می‌سازد و فایل‌های خروجی را در wwwroot بسته قرار می‌دهد.
  • محیط اجرا در هر دو خروجی Development است تا تنظیمات توسعهٔ موجود بارگذاری شود.

۲. ساخت بسته در Visual Studio

  1. پروژهٔ backend/MarketAnalyzer.Api/MarketAnalyzer.Api.csproj را باز کنید، روی آن راست‌کلیک و Publish را انتخاب کنید؛ پروفایل Local را اجرا کنید.
  2. همین کار را برای frontend/admin/MarketAnalyzer.Ui.Server/MarketAnalyzer.Ui.Server.csproj انجام دهید و پروفایل Local را انتخاب کنید.
  3. خروجی‌ها در ریشهٔ مخزن ساخته می‌شوند:
artifacts\publish\Local\Api\
artifacts\publish\Local\Ui\

Angular client را جداگانه Publish نکنید؛ UI Server ساخت و کپی آن را انجام می‌دهد.

۳. ساخت از خط فرمان

از ریشهٔ مخزن در PowerShell اجرا کنید:

dotnet publish backend/MarketAnalyzer.Api/MarketAnalyzer.Api.csproj -c Release -p:PublishProfile=Local
dotnet publish frontend/admin/MarketAnalyzer.Ui.Server/MarketAnalyzer.Ui.Server.csproj -c Release -p:PublishProfile=Local

فرمان دوم به Node.js/npm و دسترسی نصب پکیج‌های ثبت‌شده در lockfile نیاز دارد. اسکریپت پروژه پیش از build از npm ci استفاده می‌کند.

۴. کنترل خروجی و اجرای محلی

  • در هر دو پوشه بررسی کنید فایل اجرایی، web.config و appsettings.json تولید شده باشند.
  • در خروجی UI، وجود wwwroot/index.html و فایل‌های جاوااسکریپت build‌شده را بررسی کنید.
  • تنظیمات UI فعلی به API در https://localhost:7260 اشاره می‌کنند. CORS فعلی API نیز originهای http://localhost:44426 و https://localhost:44426 را مجاز می‌داند؛ پیش از اجرا، فایل‌های تنظیمات منتشرشده را با تنظیمات واقعی خودت تطبیق دهید.
  • برای اجرای نمونهٔ محلی، ابتدا API را با پورت HTTPS تنظیم‌شده اجرا کنید و سپس UI را روی origin مجاز بالا بیاورید. از پوشهٔ هر خروجی در دو پنجرهٔ PowerShell اجرا کنید:

در اجرای مستقیم فایل exe، مقدار محیط را در هر پنجرهٔ PowerShell قبل از اجرای برنامه تنظیم کنید؛ مقدار نوشته‌شده در web.config فقط هنگام میزبانی در IIS اعمال می‌شود:

$env:ASPNETCORE_ENVIRONMENT = 'Development'
./MarketAnalyzer.Api.exe --urls https://localhost:7260
$env:ASPNETCORE_ENVIRONMENT = 'Development'
./MarketAnalyzer.Ui.Server.exe --urls http://localhost:44426

گواهی توسعهٔ HTTPS باید روی همین رایانه معتبر باشد. اگر پورت یا scheme را تغییر دادید، AppOptions:ApiUrl، IdentityClientOptions:Url و CorsOptions:AllowedOrigins را هماهنگ کنید.

فایل‌های appsettings.json فعلی شامل Connection String، کلیدها و اطلاعات broker هستند. آن‌ها را در خروجی، راهنما یا مخزن عمومی منتشر نکنید. پیش از اجرای بسته، مقصد دیتابیس و سرویس‌های پس‌زمینه را حتماً کنترل کنید.

۵. محدودیت این پروفایل

Publish فقط فایل‌های خروجی را روی همین رایانه می‌سازد. این تنظیمات IIS، سرویس‌ها، دیتابیس، DNS یا داده‌های برنامه را تغییر نمی‌دهند و خروجی را به سرور منتقل نمی‌کنند. برای نصب سرور باید پروفایل و تنظیمات مخصوص همان مقصد جداگانه تعریف شود.

۶. وقتی تنظیمات پروژه عوض شد

اگر مسیر پروژه، نسخهٔ .NET، runtime/معماری، self-contained بودن، نام فایل‌های تنظیمات، پورت‌ها، مسیر API، CORS یا فرمان build کلاینت تغییر کرد، هر دو فایل Local.pubxml را با وضعیت جدید تطبیق دهید و همین راهنما را اصلاح کنید. تغییرات کاری و تنظیمات نامرتبط پروژه را وارد فرایند انتشار نکنید.
