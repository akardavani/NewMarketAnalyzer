## Current ownership and legacy boundaries

- The nine MarketData EF configurations map `CorporateActions`, `CurrentOrderBookLevels`, `CurrentSymbolStates`, `FundNavPoints`, `HistoricalCandles`, `InvestorTradingActivities`, `MarketDefinitions`, `MarketSettings`, and `MarketSymbols` to `marketdata`.
- The shared `FundDbContext` still models legacy `UnifiedCandles`, `UnifiedSymbols`, `Markets`, `Sources`, `Timeframes`, fund, and TSETMC tables. The current EF model maps those remaining entities to `marketdata`; the applied schema migration preserved their rows while moving them. Their classes and final cleanup remain deferred until replacement consumers and parity are verified.
- `UnifiedCandleQueryService` is a compatibility reader that reads `HistoricalCandles` and returns `UnifiedCandleRecord` DTOs. Legacy `CandleIngestionService` can still write `UnifiedCandles` when the old Collectors registration is used. The API's `Program.cs` does not call `AddMarketCollectors`; preserve the old project/table until its references and deployment usage have been checked.
- Repository search found no in-solution application/API consumer for `IUnifiedCandleQueryService`; it remains registered by legacy Infrastructure. `IUnifiedCandleRepository` is still referenced by the legacy Collector writer. Remove these together only at final legacy cleanup, after checking any external consumers.
- Legacy seed input files remain under `backend/MarketIntelligence/src/MarketAnalyzer.MarketIntelligence.Infrastructure/Context/Seed/`. Active symbol seeders use five of them. Fund snapshots are separately exported from their current tables. `url_settings.json` exists both under `Context/Seed/` and `Setting/`; the files are byte-identical today. The `Setting/` copy is loaded at runtime and copied to output. `IUrlSettingService` has no registered DB implementation and the refresh ZIP does not rewrite either copy.
- The old `MarketAnalyzer.MarketIntelligence.Collectors` project is still present. Its implementation must not be deleted until runtime references and the replacement collection path have been validated.
- No active strategy or API callsite remains for `IUnifiedSymbolRepository` or `IUnifiedSymbolQueryService`. Keep their contracts and implementations for legacy Collector/Fund paths until those paths are retired and external consumers are checked.

## Failure handling and access

- For a failed market or symbol, capture the real market/symbol, status, error, and retry result; continue with independent markets/symbols. Fix reproducible causes and rerun the affected scope. Record unresolved source/configuration failures with concrete samples.
- Workspace writes and Development configuration are authorized. Development now targets `localhost/MarketAnalyzer`; leave `localhost/db_MarketAnalyzer_GM` untouched. Migrations and Tools transfer are complete on the new target.
- A schema/table migration or drop is the only destructive step and remains last. If actual live ownership differs from the EF snapshot, stop that table operation and continue unrelated work.
- If build/model validation fails, fix the source or snapshot issue and rerun the relevant build/check before moving on. If a provider or symbol fails, capture its actual key/status/error, continue independent work, and retry only that scope after fixing a reproducible cause.
- User input is only needed if the source-of-truth decision for legacy URL settings changes intended runtime behavior, if an authenticated sysadmin session is unavailable for exercising the UI/export, or if live DB inventory contradicts the migration assumptions. Workspace code and docs can continue without those inputs. Do not apply schema changes or remove legacy tables while the corresponding inventory/runtime evidence is missing.
